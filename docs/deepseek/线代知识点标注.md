## 1. 背景

这是一个考研数学二刷题站。线代题库有 355 道题（书上题号 `#001`–`#355`），分六章。每章对应线代知识点文字版的一个文件：

| 章 | 名称 | 题号 | 对应的知识点文件 |
|---|---|---|---|
| L1 | 行列式 | 1–40 | `10` 行列式 |
| L2 | 矩阵 | 41–115 | `11` 矩阵 |
| L3 | 向量 | 116–146 | `12` 向量 |
| L4 | 方程组 | 147–220 | `13` 线性方程组 |
| L5 | 特征值与特征向量 | 221–284 | `14` 特征值与特征向量 |
| L6 | 二次型 | 285–355 | `15` 二次型 |

知识点文字版在 `knowledge-md/10_行列式.md` 到 `15_二次型.md`，由 31 页线代导图转写而来，按带编号的小节组织，例如 `### 3.3 可逆六充要`。每个小节有固定的 key，例如 `11/3.3`。

**任务**：给每道题标出解题时真正用到的 1–3 个知识点小节。网站会在题卡的「相关知识点」里显示这些小节，点开就是对应的知识点原文。

## 4. 工作方式：两个阶段

### 第一阶段：考点默认值 → `content/xiandai/linking/kp_defaults.json`

给 72 个考点组各定 1–3 个默认小节，作为同组题目的起点。每组看 2–3 道题再定。格式：

```json
{
  "G001": ["10/2", "10/4"],
  "G003": ["10/6.2"]
}
```

做完先运行一次校验（见第 6 节）。第一阶段的错误清零后，再进入第二阶段。

### 第二阶段：逐题标注 → `content/xiandai/linking/out/*.json`

按章分批写文件，一批 20–40 题，文件名写清章和题号范围，例如 `out/L1-001-040.json`、`out/L2-041-075.json`。校验会读 `out/` 下所有 `.json`，不需要合并。

从考点组默认值出发，读每道题，按实际解法增删。格式：

```json
{
  "questions": [
    {"num": 28, "sections": ["10/6.2"], "confidence": "high", "note": "把第一行换成系数构造新行列式"},
    {"num": 30, "sections": ["10/6.2"], "confidence": "low", "note": "解析用了两种方法，按主方法标"}
  ]
}
```

- `sections`：1–3 个 key，**最重要的放第一个**。
- `confidence`：`high` 或 `low`。
- `note`：30 字以内，写为什么这样标。下列情况**必填**：
  - `confidence` 为 `low`；
  - 主小节不在本章对应的知识点文件里（见第 1 节的表）。
  - 其他情况可选。
- **每做一批就保存一次**，中断后可以接着做。已经写好的题不要重做。
- 做完行列式这一章（40 题）后，先跑一次校验，再挑 5 道题对照目录自查，确认标的是解法而不是题面，然后再往下做。

## 5. 标注规则

1. **只用 `catalog.md` 里的 key**，不要自造。高数的 key（`01`–`09` 开头）在这里都不算。
2. **按解法标，不按题面标。** 标的是「做这道题要用到的方法或结论」。
   - 例如：题面是二次型，但关键一步是「特征值之积等于行列式」，就要标到 `14/1`，不能只标「二次型」。
3. **宁少勿滥。** 每题 1–3 个，通常 1–2 个就够。只是沾边、不影响解题的不标。
4. **主次有序。** 第一个是解题的核心步骤，后面是辅助步骤。
5. **优先选 h3**（例如 `11/3.3`），它比 h2（例如 `11/3`）具体。只有某个 h2 下面没有合适的 h3，或者整个 h2 都用得上时才选 h2。
6. **可以跨章。** 线代各章联系很紧，跨章很常见：
   - 方程组题常用到矩阵的秩（`11/4.x`）；
   - 特征值题常用到相似和实对称矩阵；
   - 二次型题常用到特征值（`14/x`）。
   - 主小节通常在本章对应的知识点文件里；如果不在，`note` 写明原因。
7. **拿不准时**：用该题考点组的默认值，`confidence` 填 `low`，`note` 写清哪里拿不准，比如看不出用哪种方法、目录里找不到合适的小节。
8. 同一考点组的题不必和默认值一致；但如果和默认值**完全不同**，要确认确实是解法不同。校验时会列出这类题。

## 6. 校验

随时可以运行：

```bash
.venv/bin/python -m pipeline.link_xiandai check
```

它会检查：

- **错误**：
  - 两个阶段的文件格式；
  - 每题 1–3 个不重复、且在目录里的 key；
  - 355 题齐全、没有重复；
  - `confidence` 的取值。
- **警告**：
  - 主小节不在本章对应的知识点文件里；
  - 结果与考点默认值完全不同。
- **说明**：低把握题号、题目最多的小节、没有题目的小节数、固定抽查的 40 题。

**完成标准**：

- 错误为 0；
- 每条警告都逐一核对过：要么改正，要么确认无误并在 `note` 里写了理由；
- 低把握题不超过 30 道。

## 7. 交回

完成后回复以下内容：

1. `check` 的完整输出。
2. 低把握的题号，以及每道题的主要原因（可以分类汇总）。
3. 第一阶段之后改动过默认值的考点组，以及改动原因。
4. 你认为题库或目录本身有问题的地方，例如：
   - 考点名明显和题目不符；
   - 某类题在目录里找不到合适的小节；
   - 目录里某个小节的标题和内容对不上。
