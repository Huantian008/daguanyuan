# 线代臻选题接入网站：DeepSeek 转写与网站空位并行

## Context

《数二线代臻选题》（355 题）和《通用答案》到了，要把线代题接进刷题站（`daguanyuan/`，线上 Worker + 本机 FastAPI 两份实现）。
和高数一样，体力活交给 opencode 里能看图的 DeepSeek：题干和答案转成 Markdown + LaTeX、线代导图知识点转文字版、逐题标注知识点。
用户要求**并行**：DeepSeek 转写的同时，我先把网站上线代需要的位置都做好；明天用户把 DeepSeek 的结果给我，我校验后直接放上去。

已确认的决定：
- 线代知识点：先把 31 页导图转成文字版，再逐题标注（标注是第三轮，等文字版合入后才能做）。
- 题号：网站显示「线001」，内部 `num = 1000 + 书上题号`（1001–1355）。进度库存的就是整数 num，**不需要迁移**。
- 线代章节代码 `L1`–`L6`（URL `/bank/L1`）。

## 摸底结论（写交接文档和代码都依赖这些）

- **题目本**（`【A4紧凑】数二线代臻选题 .pdf`，103 页，ReportLab）：355 题，六章 40/75/31/74/64/71。每题一条灰色信息条
  `#001\n行列式 → 具体行列式计算\n2014数一二三`，题身是 `fzFrm*` 表单（和高数做题本同一种 show_pdf_page 结构），整题不跨页；
  没有难度、建议分钟、原稿页。书签（TOC）给出每题完整目录路径。
- **答案本**（`【通用答案】线代臻选题.pdf`，345 页，Word 导出）：书签 A–F 章叶子数与题目本逐章**完全相同**（共 355），
  G「数学一专项」22 个叶子跳过。每题 = 题面截图 + 解析截图（部分是彩色手写）+ 有时是文字层的「答案（D）」。**线代没有答案速查**，答案要从解析里取。
- **线代知识点**（`框图版/线代大观知识点.pdf`，31 页导图）：公式基本是嵌入图片；文字层只有节点名，夹着康熙部首字符（⾏）和 0.8pt 隐形数字；
  书签给出六章页码：行列式 1–2、矩阵 3–12、向量 13–14、方程组 15–18、特征值 19–24、二次型 25–31。

## 顺序与并行

```
第一步（我，先做，约半天）：抽取 + DeepSeek 输入 + 校验工具 + 两份交接文档 → 提交 → 用户交给 DeepSeek
        ├─ DeepSeek A：线代题目转写（355 题）      ┐ 两个 opencode 会话可同时跑，各自一次只跑一批
        └─ DeepSeek B：线代知识点转文字版（31 页）  ┘
第二步（我，与 DeepSeek 同时）：网站留好线代的位置（两份实现 + 测试），数据缺失时自动退回图片
第三步（明天，用户给结果后）：check → review → 修正 → 写入 → export → 测试 → 本机验收 → 问用户是否部署
第四步（之后）：写第三份交接文档「线代知识点标注」（依赖 B 合入后的小节目录），合入标注
```

第一步必须先做：DeepSeek 要看的图片、题目清单和 `check` 命令都由它生成。

## 第一步：抽取、DeepSeek 输入、校验工具、交接文档

1. **`pipeline/sources.py`**：加 `XIANDAI_QUESTIONS_PDF`、`XIANDAI_SOLUTIONS_PDF`（`XIANDAI_PDF` 已有）。
2. **`pipeline/chapters.py`**：加线代六章 `Chapter("L1","行列式",1001,1040)` … `("L6","二次型",1285,1355)`，`XIANDAI_OFFSET = 1000`，
   `chapter_of()` 覆盖两段编号。高数 `CHAPTERS` 保持原样（`align()` 等只遍历高数）。
3. **新模块 `pipeline/xiandai.py`**（`python -m pipeline.xiandai build`），输出到独立的 `content/xiandai/`，**不碰高数的 `content/q|a|s`**
   （`pipeline.build` 全量重建会删这几个目录）：
   - 题目：复用 `questions.py` 的 `INFO_BAR`、`_content_blocks`、`_show_whole`/`widen`、`render_question`；信息条第三行就是出处，不套 `META`。
     目录路径取自 TOC：`section` = 章下第一级，`kp` = 题目上一级（直接挂在节下的题 kp 就是节名）。
   - 答案本：复用 `solutions.parse_outline`；A–F 每章叶子与题目按顺序一一对应，出处文字和叶子标题对不上的列为提示（同 `validate` 的 weak）。
   - 解析图：**按页渲染书签之间的区域**（不只抽嵌入图片），这样文字层的「答案（D）」也在图里；去掉书签标题行，`trim_whitespace`，按 `imaging.save_webp` 存。
   - 产物：`content/xiandai/q/1001.webp`、`content/xiandai/s/1001-1.webp`…，和 `content/xiandai/manifest.json`（题目记录格式见第二步的约定）。
   - 校验：355 题齐全、题图和解析图都在、每题至少一张解析图。
4. **`pipeline/transcribe_xiandai.py`**（prepare / check / review / check --write），尽量从 `transcribe_questions.py` 导入复用
   （`split_bands`、`check_entry`、`check_formulas`、`coverage`、`math_segments`、`REVIEW_STYLE`），只在那边做小的参数化，不复制逻辑：
   - `prepare` → `content/xiandai/transcribe/`：`img/qNNN.png`、`img/sNNN-k.png`（NNN 用书上题号，按 640k 像素切段），
     `questions.jsonl`（num=书上题号、chapter、chapter_name、path、kp、source、type_hint、pdf_text、solution_text、question_images、solution_images）。
   - `check`：沿用高数全部检查，另加：必填 `answer_basis`（`label`/`derived`）、开头残留「（本题满分 12 分）」「【例 1.3】」报警告、355 题齐全；
     读 `out/*.json` 全部分批文件（不需要合并步骤），`probe*` 文件除外。
   - 看图测验：#002、#013、#147。PDF 文字丢了矩阵结构；#002、#013 的题目本还印错了（丢负号、下标错），只有对照原书题面才转得对；
     #013 的答案只在手写推导里（`derived`）。
   - `review`：左边题图 + 解析图，右边渲染后的转写；默认还列出所有 `derived` 答案和 `mismatch` 题。
   - `check --write` → `bank-md/xiandai.json`（一题一行，num 存书上题号，网站加载时加 1000）。
5. **`pipeline/xiandai_knowledge.py`**（prepare / check / review）：
   - `prepare` → `content/xiandai/knowledge/`：每页一张总览 `img/pNN.png` 和高分辨率横条 `img/pNN-k.png`；`pages.jsonl`（page、所属文件、
     NFKC 归一并去掉隐形小字的节点文字提示）。
   - `check`：六个文件都在且以 `# 章名` 开头；`<!-- p.N -->` 1–31 每页恰好一次、递增、落在本章页码范围；`## N.`/`### N.M` 编号连续，
     能被 `dgy/sections.py` 的 `parse_sections` 解析；每段公式 KaTeX 编译通过、公式内无全角标点；每页节点文字找回率 < 80% 报警告；
     统计小节数和 `<!-- 待核` 条数。测验：只做第 2 页（公式全是图片），检查「范德蒙」「$(a-b)^{n-1}$」「$(-1)^{mn}$」等片段；第 4 页是文档里的示例。
   - `review`：左边原页，右边该页对应段落的渲染。
6. **测试**：PDF 解析加 `pdf` 标记测试（355 题、各章题数、#001 出处、对齐无错位）；两个 check 的规则用小样例做无 PDF 单测，
   仿 `tests/test_transcribe_questions.py`。
7. **两份交接文档**（`docs/deepseek/`，结构沿用 git 历史里 `4436246^:docs/deepseek/题目转LaTeX.md`）：
   - **`线代题目转写.md`**：背景（355 题、书上题号、没有答案速查）；环境与边界（必须能看图的模型，首选 `deepseek-v4-flash-vision-exp`；
     只写 `content/xiandai/transcribe/out/`；不提交、不 `--write`、禁止脚本批量替换）；输入；第 0 步看图测验；
     输出按批写 `out/L1-001-030.json`，字段 `num/type/stem/options/figure/answer/answer_basis/mismatch/confidence/note`；
     **题干以原书为准**：题目本是重新排版的，有印错，每题对照答案本开头的原书题面，不一致处按原书写并在 `mismatch` 记下题目本的写法；
     转写规则继承高数（照抄不解题、`$…$`、`\displaystyle`、`（　　）`、`\underline{\qquad\qquad}`、去书上题号和出处、标点照原图、只用 KaTeX 命令）
     再加线代记号：矩阵 `pmatrix`、行列式 `vmatrix`、增广/分块用 `array` 加竖线、转置 `^{\mathrm{T}}`、伴随 `A^*`、字母一律不加粗、省略号 `\cdots`/`\vdots`/`\ddots`；
     **答案规则**：图里或 `solution_text` 有「答案」就照抄（`answer_basis: label`），没有就取解析最后的结论（`derived`）；选择题只写字母，
     填空写值，解答题每问一段 ①②，证明题或证明小问写「证明见解析」，答案和解析矛盾照「答案」写并在 note 说明；
     校验、完成标准（错误 0、警告逐条核对、低把握 ≤ 40）、交回内容；我核对过的 3 个示例；
     限流教训：一次只跑一批，不开多个子代理。
   - **`线代知识点转写.md`**：背景（导图 → 六个文件 `10_行列式.md`…`15_二次型.md`，将来是网站文字版和标注小节）；只写
     `content/xiandai/knowledge/out/`；输入；第 0 步只做第 2 页；文件与页码表；结构规则（`# 章名`、来源引用行、每页开头 `<!-- p.N -->`、
     一条主干或一页标题 = `## N.`、一个框 = `### N.M`、更深的节点用 `**节点名**` 加列表、按总览图从上到下从左到右的顺序）；
     内容规则（照抄、公式 LaTeX、手写字和彩色提示进 `>` 引用块、✅ 照留、框里的例题截图写成 `**【例 2.11】**` 加原文、不描述连线、
     看不清写 `<!-- 待核：… -->`）；校验与交回；我按第 4 页写好的示例。
8. 运行 `pipeline.xiandai build`、两个 `prepare`，自己先跑一遍测验确认输入可用，提交（`feat(pipeline): …`、`docs(deepseek): …`），
   告诉用户把哪两份文档交给 DeepSeek。

## 第二步：网站留好线代的位置（与 DeepSeek 并行）

原则：数据缺什么就退回什么，明天放进 `bank-md/xiandai.json` 和 `knowledge-md/10–15_*.md` 后**不用再改代码**。

- **内容合并**：`pipeline.build` 末尾读 `content/xiandai/manifest.json`，把线代章节和题目并进主 manifest（`chapters` 加 L1–L6，
  `chapter_links` 加线代章 → 知识点 slug）。线代题记录：`num` 1001+、`chapter` L1–L6、`difficulty/stars/minutes/orig_page/quick_id` 为 `null`、
  `answer` 为 `null`、`flags` 空、图片路径 `xiandai/q/1001.webp`。`validate` 按两本书分别计数，线代不要求答案图。
- **数据模型**：`dgy/content.py`、`edge/src/content.ts` 这些字段改为可空；`tests/factories.py`、`edge/test/fixtures.ts` 加一个线代章。
- **题号**：Jinja 过滤器 `qlabel` 和 `views/util.ts` 的同名函数（num > 1000 → `线001`，否则 `#001`），替换 `_macros.html`、`question.html`、
  `search.html`、`history.html`、`views/parts.ts`、`views/bank.ts`、`views/history.ts` 里所有 `'%03d' % num` / `pad3`。
  搜索支持「线12」「线012」。题目页上一题/下一题改为同一本书内按题号找邻居（去掉写死的 `613`）。
- **题卡**：星级、建议分钟、答案速查编号、原稿页为空时不显示；没有答案图时：有文字答案显示文字，没有就显示「答案见解析」并照常给出解析。
- **题库页和首页进度**：按「高等数学」「线性代数」两组列章节；「继续往下做」高数做完接线代（`drill.onward_kp` 按章节顺序，两边都已按 chapters 走）。
- **文字版题库**：`dgy/bank.py` 的 `load_bank` 同时读 `xiandai.json`（num + 1000），`export_edge` 一并写进 `generated/bank.json`。
- **知识点**：`build_knowledge` 把单个「xiandai」条目换成六个 `10`–`15` 条目（各自的原版页图），页码范围写进新的 `knowledge-md/线代总目录.md`
  （同 `00_总目录.md` 的表格格式，不被 `[0-9][0-9]_*.md` 匹配）；`load_sections` 也读它取起始页。md 文件不存在时只显示原版（现有行为）。
  `/knowledge/xiandai` 重定向到 `/knowledge/10`。
- **不需要 D1 迁移**。行为两边一起改，各自加测试：`pytest`、`cd edge && npm test`、`npm run check`。

## 第三步：明天合入 DeepSeek 结果

1. 题目：`python -m pipeline.transcribe_xiandai check` → `review` 逐题看低把握、警告、`derived` 答案、`mismatch` 和 40 题抽查 → 必要时修正、加 `erratum`
   → `check --write` 生成 `bank-md/xiandai.json`。`mismatch` 的题：网站原图用答案本的原书题面截图，不用题目本的错图（同高数 `STATEMENT_FROM_SOLUTION`）。
2. 知识点：`python -m pipeline.xiandai_knowledge check` → `review` → 修正 → 拷进 `knowledge-md/10_…`–`15_…`。
3. `pipeline.build`、`pipeline.export_edge`，跑两边测试，本机起站浏览器验收，提交；写 `docs/releases/…`；**部署前问用户**。
4. 用第二份的小节目录写第三份交接文档 `线代知识点标注.md`（复用 `pipeline.link_questions` 的 prepare/check，参数化到线代），开始下一轮。
