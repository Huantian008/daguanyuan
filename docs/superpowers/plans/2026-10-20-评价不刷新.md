# 评价不刷新页面

## Context

题卡上每点一次「不熟练 / 不会 / 掌握」，表单都整页提交、跳回 `#q-N`，页面闪一下、重新加载，做题时很打断。
用户想要点了不刷新。讨论过两种做法：

- 先存在本机，离开页面（上一节 / 下一节、关页面）时一次性交：手机上直接划掉浏览器时那一下不一定发得出去，会丢评价；
- **点了就在后台存**（用户选的）：页面不动，评价当下就进库，点错了再点一下照旧改掉当天那条。

## 设计

- 有脚本时，`app.js` 拦下题卡评价表单的提交：按钮立刻高亮，用 `fetch` 在后台 `POST /q/<num>/grade`，
  带 `Accept: application/json`，页面不跳。没有脚本时照旧整页提交、跳回来。
- 服务端看到 `Accept: application/json` 就不重定向，回 `{"history": "<做题记录面板>"}`，脚本把它换进这张卡的
  「做题记录」，所以「下次复习」「已做 N 次」和记录都是新的。面板抽成 `history_panel` / `historyPanel`，题卡和这个回应共用。
  没登录照旧 303 去登录页，脚本看到不是 JSON 就当没存上。
- 没存上的评价：
  - 每次点评价先写进 `localStorage`（`dgy-pending-grades`，一题只留最后一次，带当天的学习日），服务器回了 JSON 才删；
  - 没存上的题在评价按钮旁边提示「还没存上，联网后会自动补交」；
  - 任何页面加载时、网络恢复（`online`）时把还在的评价再交一遍，只交当天学习日的，过了 04:00 的丢掉
    （跨天再交会算到第二天，不如不交）；
  - 同一题一次只发一个请求，发的时候又点了别的，回来后接着发最新的，保证最后存下的是最后点的。
- 再交一遍可能和上一页没来得及回的那次同时到。两个请求都看到「今天还没评」就会各插一条，所以「当天第一次」的插入改成
  `INSERT … SELECT … WHERE NOT EXISTS (当天这题已有记录)`，一条语句里判断，两次同时到也只留一条。
- 页面上随评价变的数字就地更新，不用刷新：
  - 章节页：没做过的题（题卡带 `data-new`）第一次评，标题下「做过 X / Y 题」、标题下的进度条、左边目录当前考点的
    「X / Y」和进度条都加一（`js-done` / `js-done-bar`）；
  - 热身 / 到期复习页：「今天已评 X / N 题」按页面上已高亮的题数算（`js-graded`），全评完「← 回首页」变主按钮（`js-all-graded`）。
- 不改表结构，线上不需要迁移。

## 改动

- `_macros.html` / `views/parts.ts`：`history_panel` / `historyPanel`；题卡加 `data-new`。
- `bank_chapter.html` / `views/bank.ts`、`review.html` / `views/review.ts`：计数和进度条的钩子。
- 打分路由：JSON 回应。`db.py` / `db.ts`：当天第一次的插入加 `NOT EXISTS`。
- `app.js`：后台保存、待交队列、计数更新；`app.css`：「还没存上」提示。

## 测试

- 打分路由：带 `Accept: application/json` 回 200 和做题记录面板，库里记下了；改评价后面板跟着变，仍只有一条；
  评价不对时什么都不记、面板照旧；不存在的题 404；不带这个头照旧 303。Worker 另测没登录时照旧 303 到登录页。
- 数据库层：两个「当天第一次」同时到只留一条记录（Worker 用并发的两次调用，Python 在读完之后、写之前插进另一次）。
- 页面：没做过的题卡带 `data-new`、做过的不带；章节页和复习页的计数钩子。
- 脚本：本地浏览器里验——点了不跳页、高亮、做题记录和计数更新、改评价、断网时提示并在恢复后补交。
