# 给每道题加笔记

用户想在题卡上记下解题思路，给之后复习用，参考别的刷题站的「笔记」按钮和文本框。内容用豆包输入法语音输入，纯文字就够；不做公式渲染、工具栏和笔记汇总页。用户说做好直接上线，不用先看本地效果。

## 用法

- 题卡按钮行最前面多一个「笔记」按钮，有笔记时按钮上有个小点。
- 默认收起，免得复习时还没做就先看到思路；空笔记点开后光标直接进文本框。
- 不用按保存：停顿 0.8 秒、光标离开或翻页时都会存。清空即删除。
- 章节页、热身、到期复习用同一张题卡，`/q/<题号>` 题目页也有一块，是同一条。

## 做法

- 数据：`notes` 表每题每账号一条，不留历史。本机版加在 `db.py` 的 `SCHEMA`，线上版是迁移 `0003_notes.sql`，`user_id` 不设默认值。`/settings/export` 和 `pipeline.export_progress` 都带上笔记。
- 接口：`POST /q/<num>/note`，校验 `owner`；上限 10000 字，换行统一成 `\n`；带 `Accept: application/json` 返回 JSON，否则跳回 `back`，没有脚本时靠「保存」按钮。
- 保存：`app.js` 每次改动先写 `localStorage` 的 `dgy-note-drafts:<owner>`，服务器确认后才清掉。同一题同时只发一个请求，发完如果内容又变了就再发。用 `FormData` 和 `keepalive`，百分号编码的中文可能超过 keepalive 的 64KB 限制。失败重试三次，之后在页面加载、联网、窗口获得焦点时补发；登录过期和账号改变不自动重试，分别提示。

已知限制：两台设备改同一题时，后存的覆盖先存的；本机版和线上版的笔记不自动同步，和做题进度一样。

## 验证

- Python 和 Worker 全量测试，新增：新增、修改、清空、换行、超长、题号不存在、账号不符、两个账号隔离、`</textarea>` 转义、导出、迁移；脚本的延时发送、连续输入、翻页发送、发送中又改动、失败重试和补发、登录过期、别的账号的草稿、存储被禁用。
- 用临时数据目录起本地站，真实题库：真实键盘输入后自动保存、刷新后还在且保持收起、打完字立刻翻页、停掉服务再写（内容不丢，恢复后自动补发）、清空、到期复习页、题目页快捷键、375 宽和深色模式。
- 真实的语音输入法没有测过，用键盘输入和模拟 `input` 事件代替。
