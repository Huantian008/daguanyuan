# 在 Windows 和 macOS 之间切换开发

代码走 GitHub（`https://github.com/Huantian008/daguanyuan`，Private），本机生成物和个人进度走 Google Drive。
这份文档说明哪些需要同步、哪些必须重新生成、哪些绝对不能拷。

## 1. 两台机器上的目录

| 机器 | 项目位置 | 源 PDF 位置 |
|---|---|---|
| Windows | `E:\大观园\daguanyuan` | `E:\大观园\`（仓库的上一级） |
| macOS | 建议 `~/dev/daguanyuan` | `~/dev/`（同样放上一级） |

`pipeline/sources.py` 默认去**项目的上一级目录**找 PDF，所以两台上都保持这个相对关系最省事。
放别处就用环境变量 `DGY_SOURCE_DIR` 指过去。

> macOS 上不要把项目放在 iCloud Drive（`~/Documents`、`~/Desktop` 会被强制同步）里跑。
> SQLite 数据库被同步进程同时读写会损坏。

## 2. 首次搭建

### macOS

```bash
git clone https://github.com/Huantian008/daguanyuan.git
cd daguanyuan
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd edge && npm ci && cd ..
.venv/bin/python -m pipeline.build        # 生成 content/
```

### Windows

见 `README.md` 的「第一次使用」。差异只有虚拟环境路径（`.venv\Scripts\python.exe`）。

## 3. 必须手动同步的东西（不在 git 里）

git 忽略了 PDF、`content/`、`data/` 等，所以新机器 clone 下来跑不起来，需要补这几样：

| 要拷的 | 大小 | 为什么必须 |
|---|---|---|
| 4 个源 PDF | 91.5 MB | `pipeline.build` 的输入，最大的是 `大观严选题答案.pdf`（80.6 MB） |
| `【合集】A4版知识点/` 整个目录 | — | 知识点 PDF、框图版、Markdown 复习资料 |
| `data/app.db` | 36 KB | **用户的做题记录，丢了不可恢复** |
| `data/secret_key` | 0.1 KB | 本机版的会话签名密钥 |

拷 `app.db` 之前**先关掉网站**，否则可能拷到写了一半的数据库。

### 不需要拷的（能重新生成）

| 目录 | 大小 | 怎么重新生成 |
|---|---|---|
| `content/` | 65.5 MB | `.venv/bin/python -m pipeline.build` |
| `edge/public/` + `edge/src/generated/` | 67.4 MB | `.venv/bin/python -m pipeline.export_edge` |
| `edge/node_modules/` | 228 MB | `npm ci` |
| `.venv/` | 17.8 MB | `python3 -m venv .venv`（Windows 的 `python.exe` 在 macOS 上无用） |
| `data/releases/` | 69.8 MB | 只是历次验收的本地证据，不必同步 |

## 4. Google Drive 的使用边界

**不要把整个工作副本放进 Drive 同步**，原因：

1. `.git/` 有大量零散小对象文件（近 500 个），Drive 是文件级同步，容易产生冲突副本并损坏仓库。
2. `.venv/` 和 `node_modules/` 每个平台不同，同步过去也不能用，白白占用上传时间。
3. `data/app.db` 是 SQLite 单文件库，网站运行时被 Drive 同时读写会损坏。

**推荐做法**：代码走 GitHub，Drive 只承担第 3 节那张「必须手动同步」的表（≈91.6 MB 静态文件）。
把 `data/app.db` 放进 Drive 当额外备份也可以，但同样遵守「先关网站再同步」。

## 5. 两平台命令对照

| 用途 | Windows | macOS |
|---|---|---|
| 跑网站 | `.venv\Scripts\python.exe -m dgy` | `.venv/bin/python -m dgy` |
| 重新提取题库 | `.venv\Scripts\python.exe -m pipeline.build` | `.venv/bin/python -m pipeline.build` |
| 跑 Python 测试 | `.venv\Scripts\python.exe -m pytest` | `.venv/bin/python -m pytest` |
| 导出线上资源 | `.venv\Scripts\python.exe -m pipeline.export_edge` | `.venv/bin/python -m pipeline.export_edge` |
| Worker 测试 / 类型检查 | `cd edge` 后 `npm test` / `npm run check` | 相同 |
| 启动（快捷） | 双击 `start.bat` | 无脚本，用上面的命令 |

## 6. 每次切换机器前的习惯

1. 在离开的机器上 `git status` 确认没有未提交的改动——**worktree 里的改动最容易漏**。
2. 提交并 `git push`。
3. 如果动了 `data/app.db`（刷了题），把它拷进 Drive 的同步目录。
4. 到新机器 `git pull`，然后按需从 Drive 拷回 `app.db`。
